Healthcare Eligibility Pipeline - Development Notes
===================================================

Started: January 15, 2025

## Approach

Decided to use a config-driven design where partner-specific details live in a YAML file. 
This way we can add new partners without changing code every time.

## Implementation Progress

[x] Basic pipeline structure
[x] YAML config setup
[x] Acme Health processing (pipe-delimited)
[x] Better Care processing (CSV)
[x] Data transformations (names, dates, phones, emails)
[x] Validation logic
[x] Error handling
[x] Basic tests
[x] Documentation

## Issues/Fixes

1. Phone formatting
   - Initially didn't handle phones that already had dashes
   - Fixed: strip all non-digits first, then reformat
   
2. Date parsing
   - Acme uses MM/DD/YYYY, BetterCare uses YYYY-MM-DD
   - Solution: config specifies format, code handles both
   
3. BetterCare column names
   - Their file uses "phone" not "contact_phone"
   - Updated config to match their actual columns

4. Validation
   - Decided to be strict on external_id and DOB (required fields)
   - Log warnings for invalid data but keep processing

## Tech Choices

- Python + Pandas: Good for this data size, easy to work with
- YAML for config: More readable than JSON
- Logging: Helps debug issues
- Pytest: Quick way to verify transformations work
